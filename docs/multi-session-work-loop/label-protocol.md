# 라벨 규약 — 결함·실질수정·해소의 판별 기준 (계약층 · FROZEN)

> 본 문서는 **계약층**이다. 판별 기준과 밴드 집합은 **사후 변경 금지**다.
> 지표 명세는 [measurement-design.md](./measurement-design.md), 소스 가용성은
> [measurement-feasibility.md](./measurement-feasibility.md)가 소유한다.

## 1. 출발점 — 파일 겹침은 결함 신호가 아니다

결함 정의를 "창 W 안에 같은 파일이 다시 수정됨"으로 잡으려던 초안은 **실측으로 기각됐다**.

[measurement-feasibility.md §2.4](./measurement-feasibility.md) 실측:

| 통계 | 값 |
|---|---|
| 대상 pair | 101 |
| p50 | 0.23일 |
| p90 | 1.71일 |
| 누적 ≤7일 | 99.0% |
| 누적 ≤30일 | **100%** |

즉 이 저장소의 모든 PR은 30일 안에 파일이 겹치는 후속 PR을 갖는다. 겹침 단독을 결함으로 정의하면 **전 이력이 결함**이 되고, 어떤 창 W를 골라도 판별력이 생기지 않는다.

**따라서 판별력은 창 W가 아니라 판별 기준이 담당한다.** W는 결과의 민감도를 보여주는 축으로 격하된다.

## 2. 결함 정의 (C3)

### 2.1 정의

결함 = 파일 겹침 **AND** 아래 판별 기준 중 하나 이상 충족.

| 판별 기준 | 판정 방법 | 이 코퍼스의 base rate |
|---|---|---|
| revert | PR title이 `revert` 접두이거나 본문이 되돌림을 명시 | 0 / 108 |
| fix-type | PR title이 `fix(` 접두 | 15 / 108 (13.9%) |
| finding 귀속 | 후속 PR이 선행 PR의 finding을 명시적으로 참조 | 구조화 기록 없음 — M2 전향 수집 필요 |

세 기준은 **유형별로 분리 계수**한다. 합산 단일값은 보고하지 않는다 — 어느 축이 신호를 만들었는지 사라지기 때문이다.

### 2.2 소급 C3는 산출 불가 — 정직한 선언 (Implement-Codex IF4 흡수)

세 판별 기준을 코퍼스에 적용한 결과를 있는 그대로 적는다:

| 축 | 소급 산출 가능성 |
|---|---|
| revert | **불가** — 0/108. 분자가 될 사건이 하나도 없다 |
| finding 귀속 | **불가** — 구조화 기록이 존재한 적 없다 |
| fix-type | **약한 proxy만** — 15/108. title 접두라는 얕은 신호이고, "fix(" 접두가 곧 결함 유출을 뜻하지도 않는다 |

따라서 **소급 C3는 세 축 중 둘이 분자를 0으로 만들고, 셋째는 title-prefix proxy에 불과하다.** 초안은 이를 `recoverability-undetermined`로 뭉뚱그렸으나 그건 정직하지 않다 — 결과는 이미 정해져 있다.

**선언**:

- **소급 C3(누출 결함율)는 산출하지 않는다.** revert·finding-귀속 축은 데이터 부재로 영구 불가, fix-type 축은 별도 이름 **`fix-title-proxy`** 로만 보고하며 C3 본체로 승격하지 않는다.
- C3 본체는 M2가 **`gate_decision_id → finding_id → remediation_pr`** 귀속을 전향 기록한 뒤에만 산출한다. 그 전까지 C3은 존재하지 않는 지표로 취급한다.
- [measurement-feasibility.md](./measurement-feasibility.md)의 C3 상태 `recoverability-undetermined`는 이 선언과 정합한다 — 그 라벨은 "복구 가능성이 아직 정해지지 않았다"가 아니라 "전향 귀속 기록 전까지 산출하지 않는다"로 읽는다.

### 2.3 알려진 false positive — 자기수정 사이클

본 저장소는 파이프라인이 자기 자신을 고친다. 따라서 같은 파일 재수정이 정상 작업으로도 빈번하며, 특히 아래는 결함에서 **배제**한다.

1. 같은 PRD의 연속 milestone이 같은 파일을 순차 확장하는 경우
2. 게이트 findings 흡수 사이클 — 같은 브랜치에서 리뷰 지적을 반영하는 후속 커밋
3. 버전 bump·footer 동기 같은 릴리스 메타데이터 변경
4. 문서 정정(오탈자·링크·수치 갱신)만 있는 변경

배제 규칙 없이 C3을 산출하지 않는다.

## 3. 관측 창 — 민감도 밴드 (freeze)

밴드(freeze): {1, 3, 7, 14, 30}

각 밴드는 아래와 같이 보고한다. 표의 누적 비율은 [measurement-feasibility.md §2.4](./measurement-feasibility.md)의 파일 겹침 실측이며, C3의 분자가 아니라 **겹침 자체가 얼마나 흔한지**를 보여주는 참고값이다.

| 밴드 | 겹침 누적 비율(참고) | C3 보고 |
|---|---|---|
| 1일 | 87.1% | 필수 |
| 3일 | 92.1% | 필수 |
| 7일 | 99.0% | 필수 |
| 14일 | 99.0% | 필수 |
| 30일 | 100% | 필수 |

- C3은 **밴드 5종 전부**로 산출해 함께 보고한다. 단일 창의 값만 보고하는 것은 금지다.
- **결론이 밴드 선택에 따라 뒤집히면 그 사실 자체를 결과로 보고한다.** 뒤집힘을 숨기고 하나를 고르는 것이 곧 창 길이를 조작하는 경로다.
- 밴드 집합과 매칭 규칙은 **사후 변경 금지**다. 변경 이력이 남지 않는 조정은 지표를 무효화한다.

단일 숫자 W를 고르지 않는 이유는 그 선택이 자의적이기 때문이다. 불변성은 대표성을 만들지 않으므로, 자의적 숫자를 freeze하는 대신 **자의성의 영향 범위를 보여준다**.

## 4. "실질 수정"의 기계 판별 (C2)

### 4.1 판별식

실질 수정 = 게이트 차단 판정에 귀속되는 diff가 아래를 **모두** 만족.

1. 변경이 릴리스 메타데이터·문서 정정 단독이 아님
2. 변경 파일 중 하나 이상이 차단 판정이 지목한 파일과 일치
3. 변경이 동작 분기·조건·계약에 닿음 (포맷·주석 단독 변경 제외)

### 4.2 현재 산출 금지

위 판별식의 입력은 **차단 판정 ↔ diff의 귀속 관계**인데, 이것이 현재 어디에도 기록되지 않는다. receipt의 `findings`는 거의 모든 receipt에서 비어 있고(정확한 수치는 [evidence-snapshot.json](./evidence-snapshot.json)의 `with_findings`/`parsed` — FROZEN 계약에 이동하는 코퍼스 수치를 박제하지 않는다), PR body 산문도 canonical 형식으로 파싱 가능한 행이 극소수다.

**따라서 M2가 귀속을 전향 기록하기 전까지 C2를 산출하지 않는다.** 판별식만 여기 freeze하고, 값은 만들지 않는다.

## 5. 해소 유형 분리 (C1)

finding의 종결을 아래 유형으로 분리 기록한다.

| 유형 | 해소로 계상 |
|---|---|
| 수정 반영 | 계상 |
| 설계 변경으로 무효화 | 계상 |
| 이연(backlog 등재) | **계상 금지** |
| 강등(심각도 하향) | **계상 금지** |
| 기각(YAGNI·해당 없음) | **계상 금지** |

이연·강등·기각을 해소로 계상하면 C1은 finding을 처리하지 않고도 100%가 된다. 유형 분리 없는 집계는 무효다.

## 6. 감사 표본 절차

- 표본 수: 지표별 매 측정 주기 5건
- 추출: 해당 주기 대상 모집단에서 무작위. 산출자가 고르지 않는다
- 대조: 사람이 원자료를 직접 확인해 자동 산출값과 비교한다
- 불일치 시: **해당 지표는 다음 주기까지 무효**로 처리하고, 무효 기간의 값을 추세에 포함하지 않는다
- 기록: 표본 id·판정·불일치 여부를 남긴다. 남기지 않은 감사는 수행되지 않은 것으로 본다

## 7. 이 규약이 담보하지 못하는 것

판별 기준은 기계적이지만 **정확하지 않다**. revert·fix-type은 작성자가 title을 어떻게 적었는지에 의존하고, finding 귀속은 아직 기록되지 않는다. 이 규약의 목적은 정확한 결함 탐지가 아니라 **판정 규칙을 사전에 고정해 사후 조정을 막는 것**이다. 정확도 개선은 M2 이후 별도 축이며, 개선하더라도 규칙 변경은 이력을 남긴다.
