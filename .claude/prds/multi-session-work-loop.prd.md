# Multi-Session Work Loop — 컨텍스트 한계를 넘는 작업 완주와 검증된 피드백 루프

## Problem

`/mccp:work`는 "한 번의 지시로 PRD부터 PR까지"를 목표로 만들어졌지만, 단일 세션의 컨텍스트 한계에 부딪혀 **작업 단위 하나를 사람의 수동 분할 없이 끝까지 완주하지 못한다**. 세션이 끊기면 다음 세션은 요약된 텍스트만 물려받고, 무엇이 끝났고 무엇이 실패했는지를 사람이 다시 판정해야 한다.

문제는 네 갈래로 비용을 만든다. 앞의 세 개는 **연속성 축**, 마지막 하나는 **신뢰 축**이며 둘은 같은 뿌리를 공유한다 — *증거는 쌓이는데 아무도 그것을 읽어 판정하지 않는다*.

1. **완주 실패** — 컨텍스트가 먼저 소진돼 작업이 중간에 멈춘다. 그리고 그 컨텍스트의 상당 부분을 작업이 아니라 상시 주입되는 지시문이 이미 점유하고 있다.
2. **일관성 붕괴** — 진행 상태가 사람이 손으로 관리하는 텍스트라, 세션이 늘수록 실제 상태와 어긋난다. 세션마다 다른 토글 설정이 걸리면 같은 명령이 다르게 동작한다.
3. **피드백 단절** — 한 세션에서 발견된 실수가 세션 경계를 넘지 못하고 backlog로 흘러가 사라진다.
4. **검증 실효 미상** — Codex 이중 검사가 파이프라인의 핵심 가치인데, **그 검사가 실제로 맞았는지 한 번도 측정된 적이 없다**. 헛발화 비율도, 통과시킨 뒤 터진 결함 비율도 모른다. 게이트를 늘려온 모든 판단이 무측정 신념 위에 서 있다.

Codex 이중 검사를 도입한 이유가 3번이었는데, 검사가 찾은 것이 세션 경계에서 유실되고(3번) 검사 자체의 정확도도 모르면(4번), 검사의 가치는 구조상 증명 불가능하다. 방치할 경우 mccp는 "게이트는 많은데 작업은 못 끝내고, 게이트가 도움이 됐는지도 모르는 파이프라인"으로 굳는다.

## Evidence

### 연속성 축

- **완주 실패의 직접 증거**: 본 PRD 작성 세션 시작 시점에, 이전 3개 세션이 SessionEnd 마커 없이 종료됐다는 경고가 표시됨(`06317241…`, `c81b59d0…`, `da365591…`). 정상 종료 계약이 지켜지지 않은 세션이 누적 중. **한계**: 이 증거는 비정상 종료의 존재를 보이지만, 그것이 컨텍스트 소진 때문인지 다른 원인인지는 구분하지 못한다 — 원인 귀속은 M1의 측정 설계가 해결해야 할 과제다.
- **컨텍스트 점유의 규모**: 매 세션 자동 주입되는 프로젝트 지시문이 **777줄 / 약 46,000 토큰**. 작업이 시작되기 전에 이미 상당한 예산이 소진된다. 별도로 운영 토글 문서가 존재하는데도 지시문 안에 같은 내용이 중복돼 있다.
- **일관성 붕괴의 직접 증거**: drift를 **사후 교정하기 위한 전용 명령이 두 개** 존재한다(`/mccp:dashboard-audit`, `/mccp:archive-complete`). 교정 도구가 필요하다는 것은 상태가 자동으로 어긋난다는 뜻이다. 운영 기록에도 "PRD status 테이블 in-progress drift 잔존"이 남아 있다.
- **상태 모델의 구조적 취약**: 세션 간 진실의 원천인 `STATE.md`는 **전역 단일 mutable 문서 + advisory lock**이다. 락 획득 실패 시 경고만 남기고 그대로 쓴다(last-writer-wins). 반면 세션별 ledger는 per-session 파일 + heartbeat + PID liveness로 제대로 설계돼 있으나 저활용 상태다 — **좋은 부품이 이미 있는데 진실의 원천으로 쓰이지 않는다**.
- **게이트 증거의 무보호**: 게이트 receipt는 파일 단위 원자성만 있고 동시 쓰기 보호가 없다(코드 확인 완료 — lock 미구현). 같은 작업을 두 세션이 진행하면 증거가 덮인다. receipt는 git 추적 대상이 아니라 손실 시 게이트 재실행이 유일한 복구 수단이며, 이는 파이프라인에서 가장 비싼 연산이다.
- **압축 손실**: 세션 종료 직전 컨텍스트를 6~7개 섹션 요약으로 **되돌릴 수 없게** 압축한다. 다음 세션은 요약만 받고 원본에 질의할 수단이 없다. Anthropic의 장시간 하네스 지침은 정반대를 권고한다 — *"압축·폐기에 대해 되돌릴 수 없는 결정을 내리는 대신, 이벤트 스트림을 유연하게 질의할 수 있게 하라"*.
- **요구사항 추적 부재**: Anthropic이 장시간 하네스의 필수 상태 구성요소로 꼽는 4개(Feature List / Progress File / Git / Init Script) 중 **Feature List(요구사항별 pass·fail 기계 판정)가 없다**. MAST 연구(1,600+ 실행 trace)는 멀티에이전트 실패모드 중 **"종료 조건 미인식" 12.4%**를 보고하는데, 완료 판정이 사람 손에 있는 구조가 정확히 이 실패모드다.

### 신뢰 축

- **검증 실효가 한 번도 측정되지 않음**: 124건의 게이트 증거(파싱 가능 121)와 108건의 PR 이력이 쌓여 있는데, "차단한 것 중 실제 결함은 몇 %였나 / 통과시킨 것 중 나중에 터진 건 몇 %였나"를 집계한 적이 없다.
  > **2026-07-22 정정 (M1 실측)** — 초안은 *"데이터는 있는데 판정을 안 한다"* 고 적었으나 **그 전제가 틀렸다**. 건수는 있으나 C계열이 필요로 하는 필드가 채워진 적이 없다 — receipt 121건 중 findings 보유 **1건**, `resolution.accepted`/`rejected` 빈 배열 **120건**, `codex_verdict` 부재 **90건**. findings는 PR body 산문으로 존재하나(97/108) canonical 형식 파싱 가능 행은 **2행**뿐이다. 즉 "판정을 안 한 것"이 아니라 "판정할 입력이 구조화된 적이 없는 것"이다. 이 정정은 PRD 논지를 약화시키지 않고 **강화**한다 — 측정 층 부재라는 결론은 같고 근거가 더 강해졌다. 상세·재현 명령: [measurement-feasibility.md §2](../../docs/multi-session-work-loop/measurement-feasibility.md)
- **최초의 *측정된* 게이트 실효 사례 (2026-07-22 추가)**: completion-ledger의 ship 승인 술어가 `resolution.converged`(always-true 필드)를 보고 `codex_verdict`를 보지 않는다. 결과는 **29/29 전부 `converged`**(판별력 0)이고, ship receipt와 대조 가능한 10건 중 **3건이 거짓 양성**, 19건은 receipt 소실로 대조 불가다. 통과율 100%에 실제 오류율 30% — 위 "한 번도 측정된 적 없다"에 대한 첫 반례이며, C2·C3 어느 쪽으로도 아직 계상하지 않는다(표본 10건 · 단일 게이트 · 라벨 프로토콜 확립 전 의사결정 금지).
- **배선과 발화의 괴리**: 직전 사이클(v1.22.x) PRD 자체가 *"배선은 완성됐으나 실제 LLM-runtime 발화가 관찰된 적 없음"* 을 인정하고 출발했다. 코드 30,700줄 + 테스트 47,085줄을 갖고도 **런타임에 게이트가 실제로 발화했는지를 아는 수단이 없었다**. 이는 4번 문제의 가장 선명한 사례다.
- **축의 단조 증가**: 환경 토글 **96개**(문서화 76개 — 20개는 코드에만 존재), 증거 메타 필드 **50개** / 13개 축. 도입만 있고 은퇴 절차가 없다. 상태 조합은 곱으로 늘고 테스트는 합으로 늘어난다. 멀티세션에서는 이것이 직접적 해악이 된다 — **세션마다 다른 토글이 걸리면 같은 명령이 세션별로 다르게 동작하고, 그 차이는 어디에도 기록되지 않는다.**
- **리뷰 다양성의 조용한 감소**: 교차 게이트 dedupe는 양쪽 게이트가 수렴하면 PR 단계 재검토를 생략한다. 비용상 합리적이지만 **리뷰어 수를 정확히 그만큼 줄인다**. 그 손실은 측정된 적 없다. 판정 순서·위치만 바꿔도 코드 평가 정확도가 10%p 이상 변동한다는 보고가 있는 상황에서, 단일 판정을 enum으로 고정하고 재샘플링 없이 신뢰하고 있다.
- **오류 누적의 통로**: 자동 게이트는 실패 카운터가 상한에 도달하면 사람에게 넘기며 **통과시킨다**. 장기 작업에서 초기 오류가 자동회귀적으로 누적된다는 연구에 비추면, 이 "통과"는 오류를 하류로 흘리는 통로다. 어느 단계가 원인이었는지 역추적할 기록도 없다.
- **자기 참조 과적합**: 파이프라인의 산출물이 거의 전부 파이프라인 자신의 코드다. "게이트가 통과했다"가 "산출물이 좋다"의 대리 지표로 굳는 순환이 이미 작동 중이다. 벤치마크 정렬 연구는 이 함정에서 성능이 극적으로 과장될 수 있음을 보고한다(동일 모델이 한 벤치마크 74.4% → 다른 벤치마크 11.0%).

### 측정 가능성의 한계 (정직한 기록)

기존 증거 풀로 게이트 실효 baseline을 바로 계산할 수 있다는 초기 가정은 **성립하지 않는다**. 확인된 교란 요인:

- **표본 부족·비독립**: 125 receipt / 105 PR은 게이트·버전별로 층화하면 셀당 표본이 급감한다. receipt는 같은 PR·같은 작업 안에서 상호 종속이라 독립 표본이 아니다.
- **버전 교란**: 그 기간 동안 게이트 코드와 토글 기본값이 계속 바뀌었다. 서로 다른 파이프라인의 데이터를 한 분모에 넣는 셈이다.
- **관측 공백**: 위 "배선과 발화의 괴리"대로, 게이트가 실제로 발화했는지 자체가 관측 불가능했던 구간이 있다.
- **결측**: receipt는 git 미추적이라 손실분이 얼마인지 알 수 없다.
- **판정자-채점자 미분리**: "게이트 판정이 아니라 git 이력으로 채점하므로 편향이 없다"는 주장은 틀렸다. **게이트가 차단했다는 사실 자체가 이후 커밋이 존재하는지와 무엇을 건드리는지에 영향을 준다.** 채점자가 판정자에 조건부이고 반사실(counterfactual)이 없다.

따라서 게이트 실효는 "지금 당장 계산하는 값"이 아니라 **"측정 설계부터 만들어야 하는 대상"** 이다. 이 인식이 아래 마일스톤 순서를 결정한다.

## Users

- **Primary**: mccp 운영자 본인(skypark207). 여러 Claude Code 세션을 순차·동시에 운용하며, 하나의 작업 단위를 AI에게 위임해 끝까지 맡기려는 상황에서 문제를 겪는다. 궁극적으로는 전면 자율 루프 시스템의 발판을 만드는 것이 목적.
- **Not for**: 팀 협업·다중 사용자 동기화, 원격/클라우드 분산 세션, mccp 외부 배포 사용자. 본 PRD는 단일 운영자 환경만 다룬다.

## Hypothesis

We believe **세션 스코프 상태 모델 + 증거 기반 진행 판정 + 검증 실효가 측정되는 피드백 루프**가 **컨텍스트 초과 없이 작업 단위 하나를 완주하고, 그 과정에서 생긴 실수가 다음 세션에서 자동으로 교정 대상이 되며, 그 교정이 실제로 효과가 있었는지 수치로 확인되게** 할 것이다 for **단일 운영자(skypark207)**.

### 작업 단위의 정의 (freeze — 변경 금지)

**작업 단위 1개 = PRD의 milestone 1개 = plan 1개 = PR 1개.** 이는 mccp의 기존 관례와 동일하며, 본 PRD 착수 후 **재정의·세분화할 수 없다**. 지표의 분모를 사후에 바꾸면 개선 여부를 판정할 수 없기 때문이다.

### 반증 조건 (falsification test)

지표 달성만으로는 가설이 검증되지 않는다. 아래를 만족하지 못하면 **지표가 전부 목표에 도달해도 가설은 기각**이다.

> **대표 대형 작업 코호트** — 착수 시점에 "크다"고 분류된 milestone **전부**가, **사람의 수동 분할·재정의 없이** 착수부터 PR 생성까지 완주해야 한다. 코호트는 M1에서 사전 지정하며 사후 교체할 수 없다. 현 milestone 구성에서 이 코호트는 **M4·M5 2개**다(아래 개정 이력).

이 조건이 없으면 작업을 잘게 쪼개는 것만으로 모든 지표를 만족시킬 수 있다 — 원문제(큰 작업을 한 지시로 완주)는 그대로 둔 채로.

> **개정 이력 (2026-07-22, M1 측정 결과 반영)** — 초안은 "3개 이상"을 요구했다. M1이 착수 전 불변 메타데이터 임계 규칙으로 대형 milestone을 도출한 결과, 이 PRD의 milestone 구성에서 임계를 넘는 것은 **M4·M5 둘뿐**이었다([large-cohort-registry.md](../../docs/multi-session-work-loop/large-cohort-registry.md) §3). "3개 이상"은 결과를 보기 전에 고른 임의의 수였고, 3개를 채우려 규칙을 조정하는 것은 지표 무결성 규칙 위반(결과에 맞춘 기준 조정)이다. 따라서 **반증 조건을 "대형으로 분류된 milestone 전부의 완주"로 개정**하고, 현 구성에서 그 수가 2임을 명시한다. 이는 조건의 *약화*가 아니라 *정직화*다 — "임의의 3개"보다 "규칙이 대형이라 판정한 전부"가 더 강한 요구다(개수를 못 채운다고 규칙을 못 바꾸므로). 다만 표본이 2개로 작아 반증력이 제한된다는 사실은 [large-cohort-registry.md §4.1](../../docs/multi-session-work-loop/large-cohort-registry.md)에 한계로 기록한다. 이 개정은 운영자 결정(2026-07-22)이며 M1 단독으로 내리지 않았다.

## Success Metrics

측정 층이 존재하지 않으므로 **M1이 측정 설계를, M2가 baseline을 확정**한다. 목표치는 baseline 확정 후 재조정 가능하며, 아래는 착수 시점의 제안값이다. 지표는 3계열로 묶어 판정하며, 어느 하나를 단독 최적화하면 다른 계열이 무너지도록 설계했다.

### A. 완주·연속성

| # | Metric | 정의 | Baseline | Target |
|---|---|---|---|---|
| A1 | **작업 완주율** | 작업 단위(위 freeze 정의) 착수 → PR 생성까지, **수동 분할 없이** 도달한 비율 | TBD (M2) | ≥ 80% |
| A2 | **세션 종료 컨텍스트 잔여** | 세션 종료 시점의 컨텍스트 잔여 비율 | TBD (M2) | p50 ≥ 30%, p95 ≥ 15% |

### C. 피드백·검증 실효

| # | Metric | 정의 | Baseline | Target |
|---|---|---|---|---|
| C1 | **피드백 폐쇄율** | 발견된 finding 중 같은 작업 단위 안에서 해소된 비율 | 이연 높음(정량 TBD) | 이연 **< 30%** |
| C2 | **게이트 헛발화율** | 차단 판정 중 실질 수정 없이 통과한 비율 | **측정 설계 필요** | **목표 없음 — 관측 전용** |
| C3 | **누출 결함율** | 통과 판정 후 정해진 창 안에 수정·되돌림이 붙은 비율 | **측정 설계 필요** | **목표 없음 — 관측 전용** |

**C2·C3은 성공 지표가 아니라 관측 지표다.** 목표치를 걸지 않는 이유가 셋이다. (1) 둘은 트레이드오프라 한쪽만 낮추면 다른 쪽이 오른다. (2) 검증 강도에는 보편 최적해가 없다는 것이 연구 결과다. (3) 위 "측정 가능성의 한계"대로 현재 데이터로는 편향 없는 baseline을 만들 수 없다. **C2는 특히 "실질 수정"의 기계 판별 기준이 확립되기 전까지 어떤 의사결정에도 사용하지 않는다.** 목적은 값의 개선이 아니라 **게이트별 유효 범위 판별**이다.

### 지표 무결성 규칙 (anti-gaming)

지표 자체가 값싸게 조작 가능하다는 점을 전제로 방어 규칙을 건다. 각 규칙은 해당 지표를 산출하는 시점에 함께 검사한다.

| 지표 | 알려진 조작 경로 | 방어 규칙 |
|---|---|---|
| A1 | 작업 단위를 잘게 쪼개거나 시작 이벤트를 늦게 기록 | 분모 freeze(위) + 착수 이벤트는 최초 지시 시점에 기록 + 대형 코호트 반증 조건 |
| A2 | 어려운 구간 직전에 세션을 일찍 종료 | 세션 종료 시 작업 단위 완료 여부를 함께 기록. 미완 종료는 A1 실패로 계상 |
| A3 | 지시문을 부팅 밖으로 옮기기만 하고 실제 준수율은 하락 | 감축 전후 B1·C1 회귀 검사를 통과해야 감축 인정 |
| A4 | 인계 항목을 적게·거칠게 남겨 분모를 축소 | 인계 항목 수 자체를 함께 보고. 분모가 줄면 자동 플래그 |
| B1 | 문서 status와 증거 status를 같은 소스에서 파생 | 두 소스의 독립성을 산출 시점에 검증. 동일 소스 파생이면 지표 무효 |
| B2 | 세션을 직렬화해 충돌 자체를 회피 / 감지된 것만 계수 | 동시 세션 쌍 수를 분모로 함께 보고. 분모 0이면 지표 무효 |
| B3 | 토글을 default·설정 blob 안으로 접어 수만 줄임 | 제거는 삭제가 아니라 default 고정으로만. 동작 분기 수를 함께 계수 |
| C1 | finding을 dismiss·강등해 해소로 계상 | 해소 사유를 유형별로 분리 보고. 강등·기각은 해소로 계상 금지 |
| C2 | 차단을 경고로 전환하거나 사소한 편집을 요구 | 관측 전용 강등(위). 라벨 프로토콜 확립 전 의사결정 사용 금지 |
| C3 | 관측 창을 짧게 하거나 매칭 범위를 좁힘 | 창 길이·매칭 규칙을 M1에서 고정, 사후 변경 금지 |

**감사 표본**: 매 측정 주기마다 지표별로 소수 표본을 사람이 직접 확인해 자동 산출값과 대조한다. 불일치가 발견되면 해당 지표는 다음 주기까지 무효 처리한다.

**보조 기준 — 판단용 시각화(운영자 요구사항)**: 지표는 숫자로만 존재해서는 안 되며, 기존 대시보드 표면에서 **추세와 함께** 조회 가능해야 한다. 운영자가 "지금 파이프라인이 잘 도는가"를 문서를 읽지 않고 판정할 수 있는 것이 수용 조건이다.

## Scope

**MVP** — 가설을 검증하는 최소 구성:

작업 단위 하나를 **서로 다른 두 세션이 동시에 진행해도 상태가 어긋나지 않고**, 한쪽에서 발견된 실수가 다른 쪽/다음 세션의 작업 목록에 자동으로 나타나며, **대형 작업 코호트가 수동 분할 없이 PR까지 완주**하는 것. 그리고 그 전부가 무결성 규칙을 통과한 지표로 관측되는 것.

**Out of scope**

- **게이트 강도 변경** — Codex 이중 검사, 증거 chain, dual-review 불변식은 이번 주기에 그대로 유지한다. 강도 조정은 C2·C3의 **측정 설계가 검정력을 입증한 뒤에** 근거를 갖고 하는 별도 축이다.
- **검증 앙상블·재샘플링 도입** — 판정 편향 완화는 유효한 방향이나 실효 측정 없이 도입하면 비용만 늘어난다. 후속 축.
- **외부 프로젝트 대조군** — 자기 참조 과적합 검증은 별도 축. 본 PRD는 한계를 기록만 한다. 다만 이 제약 때문에 **본 PRD의 모든 baseline은 mccp 자신에 대해서만 유효**하다는 점을 명시한다.
- **팀/다중 사용자 동기화** — 단일 운영자 전제.
- **Claude Code 네이티브 세션 기능 대체** — `--resume`, `/branch`, `/rewind`, checkpoint는 그대로 둔다. 다루는 것은 그 위층인 *작업 체인*의 연속성이다.
- **LLM 기반 실패 원인 판정** — 실패 귀속을 LLM에게 묻는 방식은 정확도가 낮다(step-level 8.7% vs 구조화 trace 34.6%). 구조화된 증거 기반으로만 판정한다.
- **병렬 워커 수 확대** — 세션 축이지 워커 축이 아니다.

### 순서의 근거

- **M1이 설계만 하는 이유** — 초안은 "측정만 하고 코드는 안 바꾼다"고 했으나 이는 **성립하지 않았다**. A1·A4·B2·C1이 요구하는 이벤트가 현재 존재하지 않아, 측정하려면 반드시 기록을 추가해야 한다. 그래서 설계(M1)와 계측(M2)을 분리했다. M1만이 진짜 무변경 단계다.
- **M3이 M5보다 앞선 이유** — 증거 덮어쓰기가 가능한 상태에서 진실원을 새 모델로 옮기면 손상된 데이터가 그대로 이전된다. 보호가 먼저다.
- **M4가 중간인 이유** — 컨텍스트 예산은 M5~M7이 모두 소비하는 자원이라 먼저 회복하면 뒤가 쉬워진다. 다만 어느 토글이 미사용인지는 M2 데이터가 있어야 알 수 있어 M2 뒤에 둔다.

## Open Questions

- [x] **결함의 정의** — M1에서 확정. 파일 겹침 **단독은 결함이 아니다**(실측: 겹침 후속수정 p50 0.23일 · 30일 내 100% → 전 이력이 결함으로 분류됨). 결함 = 겹침 **AND** 판별 기준(revert / fix-type / finding 귀속) 충족이며 유형별 분리 계수한다. 자기수정 사이클 배제 규칙 포함. → [label-protocol.md §2](../../docs/multi-session-work-loop/label-protocol.md)
- [x] **"실질 수정"의 기계 판별** — M1에서 판별식 확정. 다만 입력(차단 판정 ↔ diff 귀속)이 현재 기록되지 않으므로 **M2 전향 계측 전까지 C2를 산출하지 않는다**. → [label-protocol.md §4](../../docs/multi-session-work-loop/label-protocol.md)
- [x] **소급 감사의 유효 범위** — M1에서 프로토콜과 사전 임계로 확정. **C1**은 "불가"가 아니라 **`recoverability-undetermined`**이며, 임계(표집 40 · 파싱 60% · 일치율 75% · 셀당 5) 미달 시에만 불가로 확정한다 — C계열 중 유일한 소급 프로토콜 대상이다. **C2·C3은 `forward-only`**로, label-protocol이 이미 전향 기록 전 산출 금지를 확정했으므로 프로토콜 대상이 아니다(두 라벨을 혼용하지 않는다). A2·A4·B2는 텔레메트리 부재로 불가, B3 가능, **A1은 forward-only(소급 baseline 없음 — ledger `verdict` 판별력 0으로 대조 불가, §4는 C1 전용)**, B1 부분. → [measurement-feasibility.md §3-4](../../docs/multi-session-work-loop/measurement-feasibility.md)
- [x] **대형 작업 코호트의 기준** — M1에서 임계 규칙 freeze. 입력은 착수 전 불변 메타데이터(참조 지표 수 · Risks 지목 수 · 코드 변경 선언)만 쓰고, PRD 스냅샷을 sha256으로 pin해 사후 이동을 차단했다. 임계 3을 넘는 milestone은 **M4·M5 2개**이며, 초안이 요구한 3개에 미달했으나 임계를 낮추지 않고 반증 조건을 개정했다(위 반증 조건 §개정 이력). → [large-cohort-registry.md](../../docs/multi-session-work-loop/large-cohort-registry.md)

- [ ] **이력 보존 정책** — 질의 가능한 이력은 무한 증가한다. 보존 기간·압축 시점·용량 상한.
- [ ] **점유 만료와 재생 방어** — 작업을 잡은 세션이 비정상 종료했을 때 점유를 언제 회수하고, 회수 후 원 세션이 되살아나 쓰는 기록을 어떻게 무시할 것인가. 세션 epoch·순번·tombstone 중 무엇을 쓸지.
- [ ] **최소 지시 계약** — M4에서 무엇을 반드시 상시 유지하고 무엇을 요청 시 로드로 돌릴 것인가. 임계는 현재 미상.
- [ ] **피드백 자동 승격의 경계** — 모든 finding을 다음 세션 작업 목록에 올리면 노이즈가 된다. 어떤 심각도부터 자동 승격할 것인가.

### 연구 — 검증 실효·신뢰 축

- *The Intervention Paradox* (arXiv 2602.03338) — 오프라인 AUROC 0.94의 우수한 비평가도 최악의 경우 26%p 성능 악화. 개입이 이득이 되는 조건이 실환경에서 일상적으로 위배됨

- *The Verification Horizon: No Silver Bullet for Coding Agent Rewards* (arXiv 2606.26300) — 검증 방식마다 유효 범위가 있고 보편 최적해는 없음
- *Judging the Judges* / *Self-Preference Bias in LLM-as-a-Judge* (arXiv 2410.21819 외) — 판정 위치만 바꿔도 코드 평가 정확도 10%p 이상 변동
- *UTBoost* (arXiv 2506.09289) — 엄격 검증 시 에이전트 공식 성능이 성립하지 않음. 테스트 통과 ≠ 정확
- *FeatureBench* (arXiv 2602.10975) — 동일 모델이 한 벤치마크 74.4% → 다른 벤치마크 11.0%
- *Where LLM Agents Fail and How They can Learn From Failures* (arXiv 2509.25370) — 장기 작업에서 초기 오류의 자동회귀적 복리 누적
- *Seeing the Whole Elephant* (arXiv 2604.22708) — 실패 귀속: full trace vs output-only에서 agent-level 65.9%/51.0%, step-level 30.3%/16.0%
- *Towards Self-Improving Error Diagnosis* (arXiv 2604.17658) — step-level 귀속 34.6% vs LLM-as-Judge 8.7%
- *Confidence Improves Self-Consistency* (arXiv 2502.06233) — 신뢰도 가중 다수결로 표본 40% 절감. **본 PRD out-of-scope, 후속 축**
