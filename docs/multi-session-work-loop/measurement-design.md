# 측정 설계 — 지표 계약 (계약층 · FROZEN)

> 본 문서는 **계약층**이다. 분모·산출식·무결성 검사는 corpus 상태와 무관하게 유효하며 **사후 변경 금지**다.
> 어느 소스가 지금 쓸 만한지는 [measurement-feasibility.md](./measurement-feasibility.md)(가용성층, PROVISIONAL)가 소유한다.
> 결함·실질수정·해소의 판별 기준은 [label-protocol.md](./label-protocol.md)에 있다.

## 1. 작업 단위 정의 (PRD freeze 재기재 — 변경 금지)

**작업 단위 1개 = PRD의 milestone 1개 = plan 1개 = PR 1개.**

이 정의는 PRD가 freeze한 것이며 본 문서가 재기재할 뿐이다. 착수 후 재정의·세분화할 수 없다. 지표의 분모를 사후에 바꾸면 개선 여부를 판정할 수 없기 때문이다.

착수 이벤트는 **최초 지시 시점**에 기록한다. 늦게 기록하면 A1의 분모가 줄어 완주율이 부풀려진다.

## 2. 명세 형식

지표 10개를 각각 6개 고정 라벨로 명세한다. 라벨 문자열은 Validation이 기계 검증하므로 임의 변경하지 않는다.

`분모` / `분자` / `소스` / `산출식` / `무결성 검사` / `소급 가부`

`무결성 검사`는 PRD의 anti-gaming 표를 **산출 시점에 실행되는 검사**로 번역한 것이다. 검사에 걸리면 해당 지표는 그 주기에 **무효**이며, 무효를 정상값으로 대체하지 않는다.

## 3. A 계열 — 완주·연속성

### A1 작업 완주율

- 분모: 착수 이벤트가 기록된 작업 단위 전수. §1 freeze 정의를 따르며 사후 분할 금지
- 분자: 수동 분할·재정의 없이 PR 생성까지 도달한 작업 단위 수
- 소스: 착수·종료 이벤트(M2 신설) + PR 이력. completion-ledger는 링크 용도로만 사용하고 판정에는 쓰지 않는다
- 산출식: 분자를 분모로 나눈 비율. 미완 종료는 완주 실패로 계상하며 미판정으로 남기지 않는다
- 무결성 검사: 작업 단위 수가 직전 주기 대비 비정상 증가하면 분할 의심으로 플래그. 착수 이벤트 시각이 최초 지시 시각보다 늦으면 해당 건 무효
- 소급 가부: **forward-only (소급 baseline 없음)** — ship 기록이 불완전(ledger 23/33 미기록)하고 ledger `verdict`는 판별력 0(대조 가능 10건 중 3건 false positive)이라 대조 소스로 쓸 수 없다. §4 recoverability 프로토콜은 **C1 전용**이며 A1 recovery 절차를 정의하지 않는다(measurement-feasibility.md §4.0). 따라서 A1 baseline은 소급하지 않고 M2가 착수·종료 이벤트로 **전향 수립**한다(A2·A4와 동일 취급). ledger를 A1 소급 대조 소스로 재사용하는 것은 손상된 술어(`resolution.converged` always-true) 재사용이므로 금지한다 (Codex R3 F2 흡수)

### A2 세션 종료 컨텍스트 잔여

- 분모: 종료 이벤트가 기록된 세션 전수
- 분자: 해당 세션 종료 시점의 컨텍스트 잔여 비율. p50·p95를 함께 보고한다
- 소스: 세션 종료 이벤트에 stamp된 컨텍스트 잔여 비율(M2 신설). 현재 이 값을 남기는 소스가 없다
- 산출식: 잔여 비율의 분위수. 단일 평균은 보고하지 않는다 — 조기 종료가 평균을 왜곡한다
- 무결성 검사: 세션 종료 시 작업 단위 완료 여부를 함께 기록한다. 미완 종료 건이 늘면 A1 실패로 계상하며, A2만 좋아지는 조합은 무효로 처리
- 소급 가부: 불가 — 텔레메트리가 존재한 적이 없다

### A3 상시 지시문 점유율

- 분모: 세션 시작 시점의 총 컨텍스트 예산 토큰 수
- 분자: 작업 시작 전 자동 주입된 지시문이 점유한 토큰 수
- 소스: 아래 실행 규칙이 지정하는 정확한 파일 집합 + 명시된 tokenizer. 바이트 기반 추정은 한국어에서 성립하지 않으므로 금지한다
- 산출식: 분자를 분모로 나눈 비율. baseline과 감축 후 값을 **동일 tokenizer·동일 파일 집합**으로 산출하며, 둘 중 하나라도 바뀌면 baseline을 재산출한다
- 무결성 검사: 감축 전후로 B1·C1 회귀 검사를 통과해야 감축을 인정한다. 지시문을 부팅 밖으로 옮기기만 하고 준수율이 떨어지면 감축이 아니다
- 소급 가부: **`baseline-unavailable`** — 현재 값은 산출 가능하나 PRD baseline은 방법 미기재라 그대로 쓸 수 없다. M2 계측 전까지 산출하지 않는다(아래 강등 규칙 + measurement-feasibility.md §3과 동기화, Implement-Codex F2 흡수)

**실행 규칙 (IF2 흡수 — 두 구현자가 같은 값을 내도록)**:

- **tokenizer**: `tiktoken` 패키지의 `o200k_base` 인코딩(현행 Claude/GPT 계열 근사). 버전은 산출 시점에 `pip show tiktoken`으로 기록한다. tokenizer를 바꾸려면 baseline을 재산출하고 변경 이력을 남긴다.
- **분자의 파일 집합**: 세션 시작 시 자동 주입되는 것 전부 — (1) `CLAUDE.md`, (2) `~/.claude/.../memory/MEMORY.md`(인덱스만, 개별 memory 본문 제외), (3) SessionStart hook이 주입하는 STATE.md 블록. slash-command 본문·skill 정의는 요청 시 로드이므로 **제외**한다.
- **분모**: 세션의 총 컨텍스트 윈도로, 산출 시점 모델의 공표 컨텍스트 길이를 기록한다(예: 200,000). 추정하지 않고 문서화된 값을 쓴다.
- **worked example** (2026-07-22 관측): `CLAUDE.md` = 139,335바이트. `o200k_base` 토큰 수는 `len(enc.encode(open('CLAUDE.md').read()))`로 산출한다 — 이 값이 A3 분자의 CLAUDE.md 성분이다. 바이트/4 추정(≈34,834)은 24% 오차이므로 **쓰지 않는다**.

**A3 baseline은 현재 unavailable — M2 계측 전까지 산출하지 않는다 (Implement-Codex R2-F3 흡수)**:

M1은 A3의 *방법*만 freeze하고 *baseline 값*은 만들지 않는다. 이유는 정직하게 기록한다 — 분자 성분 세 개 중 둘이 fresh clone에서 재현 불가다:

- `CLAUDE.md`: 재현 가능(repo 내 파일, 해시 가능).
- `MEMORY.md` 인덱스: **user-level 경로**(`~/.claude/.../memory/MEMORY.md`)라 repo 밖이고 사용자마다 다르다. 정확 경로·해시를 M1이 고정할 수 없다.
- SessionStart STATE.md 주입 블록: hook이 런타임에 합성하며 세션마다 내용이 다르다. 정적 경계·해시가 없다.

따라서 A3 baseline은 **M2가 실제 주입 payload를 계측 시점에 기록**해야만 확정된다(주입된 3성분의 정확한 바이트열 + 각 해시 + tokenizer 버전 + 토큰 수를 한 번에 stamp). M1은 이 계측을 **M2 수용 조건**으로 넘긴다. 그 전까지 A3 소급 가부는 위 "부분"이 아니라 **`baseline-unavailable`**로 강등한다 — [measurement-feasibility.md §3](../../docs/multi-session-work-loop/measurement-feasibility.md)의 A3 상태와 동기화한다.

### A4 세션 경계 복원율

- 분모: 세션 N이 남긴 작업 상태 항목 수
- 분자: 세션 N+1이 실제로 복원한 항목 수
- 소스: 인계 항목 이벤트(M2 신설). 현재 session ledger는 0건이다
- 산출식: 분자를 분모로 나눈 비율. 인계 항목 수 자체를 함께 보고한다
- 무결성 검사: 분모가 직전 주기 대비 줄면 자동 플래그. 인계를 적게 남겨 분모를 축소하는 경로를 차단한다
- 소급 가부: 불가 — 인계 항목이 구조화 기록된 적이 없다

## 4. B 계열 — 일관성·충돌

### B1 진행 상태 drift

- 분모: 문서에 status가 기록된 작업 단위 전수
- 분자: 문서 status와 독립 증거 판정 status가 불일치한 건수
- 소스: 문서 status는 PRD·plan 본문, 증거 status는 **문서에서 파생되지 않은** 소스. ledger는 판정 소스로 쓰지 않는다
- 산출식: 불일치 건수의 절대값을 보고한다. 비율이 아니라 건수다 — 목표가 0건이기 때문
- 무결성 검사: 두 소스의 독립성을 산출 시점에 검증한다. 동일 소스에서 파생된 것으로 확인되면 그 주기의 B1은 무효
- 소급 가부: 부분 — 문서 status는 읽히나 독립 증거 소스가 현재 무신호다

### B2 동시 세션 충돌 사고

- 분모: 동시에 활성이었던 세션 쌍의 수
- 분자: 두 세션이 같은 작업·증거를 덮어쓴 사고 건수
- 소스: 세션 활성 구간 기록 + 충돌 이벤트(M2 신설)
- 산출식: 분모와 분자를 **함께** 보고한다. 분자만 보고하는 것은 금지
- 무결성 검사: **분모가 0이면 지표 무효**다. 세션을 직렬화해 충돌을 회피한 것과 충돌이 없었던 것을 구분하지 못하기 때문
- 소급 가부: 불가 — 동시 세션 쌍이 기록된 적이 없다

### B3 활성 축 수

- 분모: 코드에 존재하는 환경 토글 전수
- 분자: 실제 non-default 사용 이력이 있는 토글 수
- 소스: 아래 실행 규칙이 지정하는 코드 스캔 + 사용 이력 기록(M2 신설)
- 산출식: 전체 수와 사용률을 함께 보고하고, **동작 분기 수**를 병기한다
- 무결성 검사: 제거는 삭제가 아니라 default 고정으로만 인정한다. 토글을 설정 blob 안으로 접어 수만 줄이면 동작 분기 수가 그대로이므로 병기된 분기 수가 이를 드러낸다
- 소급 가부: 가능 — 전수는 오늘 산출된다. 사용 이력만 전향 수집이 필요하다

**실행 규칙 (IF2 흡수)**:

- **토글 식별자**: 정규식 `MCCP_[A-Z0-9_]+`에 매치되는 토큰. 이 prefix 규약이 mccp 토글의 정의다.
- **분모의 스캔 범위**: `plugins/mccp/scripts/` 하위 `*.js` 중 `*/tests/*` 경로와 `*.test.js` 파일을 **제외**한 것. 테스트가 만드는 mock 토글이 분모를 오염시키지 않게 한다.
- **동작 분기 수**: 토글 하나가 몇 개의 서로 다른 값으로 분기하는지의 합. 예를 들어 `MCCP_STOP_LOOP`(off/observe/enforce 3분기)은 분기 3, 불리언 토글은 분기 2로 센다. "토글 수를 줄였다"가 "동작 분기를 줄였다"와 다름을 이 병기가 드러낸다.
- **worked example** (2026-07-22, [evidence-snapshot.json](../../docs/multi-session-work-loop/evidence-snapshot.json) `toggles`): 비-테스트 코드 스캔 = **96**, `CLAUDE.md` 문서화 = 55, `docs/ENVIRONMENT.md` = 38, 두 문서 union = 82. 즉 코드에 96개가 있고 그중 문서화된 것은 82개(14개는 코드에만 존재). 분모는 96, 사용 이력(분자)은 M2 전향 수집 전까지 미상. B3 목표(전체 ≤ 40)는 96에서 출발한다.

## 5. C 계열 — 피드백·검증 실효

> **C2·C3은 관측 전용이다.** 목표치를 걸지 않으며, [label-protocol.md](./label-protocol.md)가 확립되기 전에는
> **어떤 의사결정에도 사용하지 않는다**. 목적은 값의 개선이 아니라 게이트별 유효 범위 판별이다.

### C1 피드백 폐쇄율

- 분모: 발견된 finding 전수
- 분자: 같은 작업 단위 안에서 해소된 finding 수
- 소스: finding 생성·해소 이벤트(M2 신설). 현재는 PR body 산문과 backlog 6행뿐이다
- 산출식: 해소 비율. 이연률을 함께 보고한다
- 무결성 검사: 해소 사유를 유형별로 분리 보고하며 **강등·기각은 해소로 계상 금지**. 유형 분리가 없는 집계는 무효
- 소급 가부: recoverability-undetermined — 프로토콜 미실행

### C2 게이트 헛발화율

- 분모: 게이트가 차단 판정을 내린 건수
- 분자: 그중 실질 수정 없이 통과한 건수
- 소스: 차단 판정 기록 + 그 판정에 귀속되는 diff(M2 신설). 현재 이 귀속이 기록되지 않는다
- 산출식: 비율을 게이트별로 분리 산출한다. 게이트를 합산하면 유효 범위 판별이라는 목적이 사라진다
- 무결성 검사: 차단을 경고로 전환하거나 사소한 편집을 요구해 분자를 줄이는 경로를 차단한다. 관측 전용이므로 값의 개선 자체를 성과로 보고하지 않는다
- 소급 가부: recoverability-undetermined — 프로토콜 미실행

### C3 누출 결함율

- 분모: 게이트를 통과한 판정 건수
- 분자: 정해진 창 안에 수정·되돌림이 붙은 건수. 판별 기준은 label-protocol이 소유한다
- 소스: 통과 판정 기록 + PR·커밋 이력
- 산출식: 관측 창을 **민감도 밴드 5종 전부**로 산출해 함께 보고한다. 단일 창의 값만 보고하는 것은 금지
- 무결성 검사: 창 길이와 매칭 규칙은 label-protocol에 freeze되어 있으며 사후 변경 금지. 결론이 밴드 선택에 따라 뒤집히면 그 사실 자체를 결과로 보고한다
- 소급 가부: recoverability-undetermined — 프로토콜 미실행

## 6. M2가 전향 기록해야 할 이벤트 (지표에서 역산 — M1은 구현하지 않는다)

| 이벤트 | 필요한 지표 |
|---|---|
| 작업 단위 착수 (최초 지시 시각) | A1 |
| 세션 종료 (+ 컨텍스트 잔여, 작업 단위 완료 여부) | A1 · A2 |
| 인계 항목 생성·복원 | A4 |
| 세션 활성 구간 + 충돌 발생 | B2 |
| 토글 non-default 사용 | B3 |
| finding 생성·해소 (+ 해소 유형) | C1 |
| 게이트 판정 + 그 판정에 귀속되는 diff | C2 · C3 |

M2의 수용 조건에 **추가 LLM 호출 금지**가 걸려 있으므로, 위 이벤트는 전부 구조화 데이터로만 기록한다.

## 7. 감사 표본

매 측정 주기마다 지표별로 소수 표본을 사람이 직접 확인해 자동 산출값과 대조한다. 불일치가 발견되면 해당 지표는 다음 주기까지 무효 처리한다. 표본 수와 추출 방법은 [label-protocol.md](./label-protocol.md) §5가 소유한다.
