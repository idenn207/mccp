## Q2 — child Claude cost-state isolation (Open Question #2)

### Evidence

`cost-current.json` path resolution is **hardcoded to user-level homedir** with NO env override:

```javascript
// plugins/mccp/scripts/lib/cost-state-path.js:15-21
function getCostStateDir() {
  return path.join(os.homedir(), '.claude', 'plugins', 'data', 'mccp');
}
function getCostStatePath() {
  return path.join(getCostStateDir(), COST_STATE_FILENAME);
}
```

This is `EVIDENCED`. Both writer ([cost-state.js:140-160](../../plugins/mccp/scripts/lib/cost-state.js#L140-L160)) and reader (auto-chain.js) go through these helpers. No `MCCP_COST_STATE_DIR` exists anywhere in mccp ([grep `MCCP_COST_STATE_DIR` → No matches found]).

### Hook point to introduce isolation

The cleanest single-point change is in [cost-state-path.js:15-17](../../plugins/mccp/scripts/lib/cost-state-path.js#L15-L17):

```javascript
function getCostStateDir() {
  const override = process.env.MCCP_COST_STATE_DIR;
  if (override && override.trim()) return override;
  return path.join(os.homedir(), '.claude', 'plugins', 'data', 'mccp');
}
```

Spawner ([session-spawner.js:114-126](../../plugins/mccp/scripts/state/session-spawner.js)) already accepts an `env` parameter — child spawn can be passed `env: { ...process.env, MCCP_ORCHESTRATED_CHILD: '1', MCCP_COST_STATE_DIR: '<per-child-tmpdir>' }`. The wrapper change is ~3 lines.

### Infinite-spawn-loop walk-through (parent shares cost-state with child)

Code path under v0.3.0 auto-handoff if isolation is NOT introduced:

1. Parent's `ecc-context-monitor.js` writes `cost_usd >= critical` to `~/.claude/plugins/data/mccp/cost-current.json` via [cost-state.js:140 writeStateMerged](../../plugins/mccp/scripts/lib/cost-state.js#L140) (UNCONDITIONAL monotonic merge — line 9-12 invariant says stale "hard_ceiling=true" is sticky).
2. Parent Stop hook → [auto-handoff.js:71-138 run()](../../plugins/mccp/scripts/hooks/auto-handoff.js#L71-L138) → `decision.shouldHandoff=true` → calls `spawner.spawn(...)`.
3. Child Claude inherits parent env → `cost-state-path.js:15` returns same homedir path → reads same `cost-current.json` with `hard_ceiling_reached:true` still present (sticky per [cost-state.js:120-138 mergeMonotonic](../../plugins/mccp/scripts/lib/cost-state.js#L120-L138)).
4. Child's first Stop hook fires → `detector.detect()` returns `tier=critical` again → child also calls `spawner.spawn()` → grandchild.
5. **Only saving grace today**: `session-spawner.js:65-74 taskHash(tier, currentTask)` — if parent and child read same STATE.md `task_fingerprint`, the lock path collides → child's `tryAcquireLock` finds lock held → returns `ok:false reason:'lock-held'`. So the existing race-lock partially mitigates.
6. **But the lock IS process-isolated**: parent's lock has `pid=parent.pid`, child sees `pid is dead` only when parent actually exits → during parent + child concurrent window, lock holds. After parent exit, child reads `pid dead` → reclaims → grandchild path opens.

**Verdict**: existing race-lock prevents same-cycle storm but does NOT prevent generation N+1 from re-entering critical tier. Isolation is REQUIRED for v0.4.0 if child Claude actually does work that costs money.

### Recommended isolation contract (PRD-input)

| Env var | Set by | Effect |
|---|---|---|
| `MCCP_ORCHESTRATED_CHILD=1` | spawner when forking child | auto-handoff.js short-circuits to `noop` regardless of tier (recursion guard) |
| `MCCP_COST_STATE_DIR=<per-child-path>` | spawner | child's cost-state lives in `<root>/.claude/state/orchestrated-<pid>/` |
| Parent reads child telemetry from above dir at child exit | future axis E (shared ledger) | aggregate into parent state |

`NO_EVIDENCE` for a precise number. Reasoning:

### Auto-handoff is the v0.4.0 axis C prototype

[auto-handoff.js:71-138 run()](../../plugins/mccp/scripts/hooks/auto-handoff.js#L71-L138) already implements the on-demand spawn pattern:

- mode tri-state `off | notify (default) | spawn` per [session-spawner.js:12-17](../../plugins/mccp/scripts/state/session-spawner.js#L12-L17)
- spawn mode degrades to notify if claude binary missing or tmux absent on non-win32 ([session-spawner.js:53-57](../../plugins/mccp/scripts/state/session-spawner.js#L53-L57))
- race-lock pattern via `ownership_token_hash` + host-aware tri-state ([session-spawner.js:19-24](../../plugins/mccp/scripts/state/session-spawner.js#L19-L24))
- ledger at `.claude/state/auto-handoff-log.jsonl`
- exit ALWAYS 0 (fail-open per [auto-handoff.js:14](../../plugins/mccp/scripts/hooks/auto-handoff.js#L14))

This is **80% of axis C already done**. v0.4.0 should EXTEND auto-handoff.js rather than build a new orchestrator hook.

### Deadlock — Stop hook fires recursively

Walk-through of the recursion path with NO `MCCP_ORCHESTRATED_CHILD` guard:

1. Parent Stop hook → `auto-handoff.js` → `decision.shouldHandoff=true` (tier=critical).
2. `session-spawner.js:spawn()` → child_process.spawn of claude binary.
3. Child claude inherits parent env → child also has `MCCP_AUTO_HANDOFF=spawn` (per parent's settings).
4. Child does first response → child Stop hook fires → child's auto-handoff.js runs.
5. Child reads `cost-current.json` from SAME path (Q2 finding) → tier already `critical` (sticky monotonic merge per [cost-state.js:120-138](../../plugins/mccp/scripts/lib/cost-state.js#L120-L138)).
6. Child tries `spawner.spawn()` → calls `tryAcquireLock(<task_hash>)`:
   - If parent still alive AND lock pid still matches: child sees lock held → `ok:false reason:'lock-held'` → child does noop → child continues normally → next Stop fires → repeats.
   - If parent exited: child's reclaim succeeds → grandchild spawned → infinite chain.

### Recommended guard pattern (PRD-input)

Two-layer guard, both required:

```javascript
// guard layer 1 — auto-handoff.js entry point
if (process.env.MCCP_ORCHESTRATED_CHILD === '1') {
  appendLedger(root, { ts, mode: 'child-noop', reason: 'orchestrated-child' });
  return { telemetry: { ok: true, mode: 'child-noop' } };
}

// guard layer 2 — session-spawner.js spawn env injection
const childEnv = Object.assign({}, parentEnv, {
  MCCP_ORCHESTRATED_CHILD: '1',
  MCCP_COST_STATE_DIR: path.join(root, '.claude', 'state', `orchestrated-${process.pid}`),
});
```

Why both:
- Layer 1 alone fails if parent env doesn't propagate (Windows spawnSync env inheritance edge cases).
- Layer 2 alone fails if child still runs `auto-handoff` (cost-state isolation only delays the trigger).

The existing race-lock (`session-spawner.js:84-114`) is good as a tertiary defense but should NOT be the primary recursion gate. Locks model concurrent same-cycle stampedes, not generational descent.
