## Findings

| Perspective | Severity | Claim | Evidence |
|---|---|---|---|
| architect | HIGH | Acceptance criteria contradicts documented design decision on exec_path storage | Plan §Design Decisions line 279 explicitly states '`exec_path`는 **절대경로를 그대로** 넣는다' (exec_path stored as-is in absolute path form). The justification states normalization breaks D15 identity verification because 'basename(<outside-repo>) doesn't appear in commandLine'. However, Plan §Acceptance line 457 lists '**경로 비-누출** — repo 밖 `execPath`가 `<outside-repo>`' (path leakage — execPath outside repo [should be] <outside-repo>). These are mutually exclusive: (1) absolute paths stored, (2) repo-external paths normalized to `<outside-repo>`. An implementer cannot satisfy both. The contradiction makes it ambiguous which requirement will be tested for acceptance. |
| architect | MEDIUM | Process start time capture not enforced to occur early in process lifecycle | Plan §D15 line 123 specifies registration captures 'proc_started_at_ms' via 'Math.round(Date.now() - process.uptime() * 1000)'. Task 3 (dashboard) and Task 4 (plan-codex-runner) both specify registration happens after other startup code (line 303: 'startServer의 writeServerPid(...) 직후', line 310: 'lock 획득 직후'). The 2000ms tolerance (line 134) is meant to absorb 'spawn delay', but there is no documented requirement that registration must occur within a bounded time from process start. If a process delays significantly before calling register(), the proc_started_at_ms will be stale, potentially causing identity_mismatch at SessionEnd. The plan leaves this as an implementation detail without explicit constraint. |
| architect | MEDIUM | Staleness threshold for orphan session detection undefined | Task 10 specifies '세션(= `session_pid` 사망 또는 `null`+디렉토리 mtime 오래됨) 디렉토리' (dead session = session_pid dead OR directory mtime is old). The word 'old' (오래됨) is never quantified with a time constant. Task 10 Validate section (line 373) specifies only 'dead 세션의 live pid 카운트' without stating the staleness threshold. This leaves the implementer to guess: is 5 seconds old? 30 days old? This ambiguity could result in stale sessions being misclassified as live or live sessions not reported as orphans. No precedent staleness constant is cited (e.g., from hook-trace LRU eviction). |
| security | CRITICAL | exec_path storage mode is contradictory: plan requires storing absolute paths (D15, line 279) for identity verification to work, but acceptance criteria (line 457) requires normalizing to '<outside-repo>' for path non-leakage, which are mutually exclusive | Plan D15 (line 279): 'exec_path는 절대경로를 그대로 넣는다... 이전 판은 normalizeReceiptCwd로 정규화해 repo 밖을 <outside-repo>로 바꿨는데, 그러면 §D15의 basename(exec_path) 대조가 구조적으로 항상 실패한다' vs. Acceptance (line 457): '경로 비-누출 — repo 밖 execPath가 <outside-repo>'. If exec_path is normalized to '<outside-repo>', then basename('<outside-repo>') = 'outside-repo', which will never appear in real command lines like '/usr/bin/python3' or 'powershell.exe', causing D15 identity verification to always fail for any process outside repo (which includes handoff sessions per Task 5). This breaks the PRD Success Metric 'osal 0' for handoff-session kind. |
| security | HIGH | Identity verification through basename matching is untested in plan; no test ensures that probe.commandLine actually contains path.basename(record.exec_path) for real processes | Plan Task 1 Validate (line 287-289) requires tests but line 5 in Validation checklist shows these are '산출물' (output of this plan), not existing tests. D15 (lines 134, 269) proposes: 'probe.commandLine이 path.basename(record.exec_path)를 포함' but no existing code path exercises this comparison. For handoff-session (powershell.exe) and dashboard-server (__filename), this comparison is hypothetical and untested. |
| security | HIGH | writePrivate() in plan-codex-runner.js lacks directory creation, causing silent registration failure when session directory doesn't exist | plan-codex-runner.js lines 75-79 show writePrivate() writes directly without mkdir. Task D8 (line 162) identifies this: 'writePrivate(plan-codex-runner.js:75-79)는 tmp write + rename만 하고 mkdir을 하지 않는다'. The plan says Task 1 must add mkdir, but this is a critical dependency not yet implemented. Acceptance line 455 claims 'direcotry 부재에서도 등록이 성공' must pass, but the code path doesn't guarantee this. If registration fails silently, the session will appear to have no processes, satisfying kill-gate acceptance but leaving processes orphaned. |
| security | MEDIUM | repo_root cross-repo detection via realpathSync has insufficient fallback for symlink attacks | Plan D4 (line 96): 'canonical(record.repo_root) !== canonical(repoRoot)' uses 'fs.realpathSync.native 정규화 후 — symlink 경유 경로가 오탐으로 cross_repo를 내면 회수가 조용히 전멸한다'. Fallback (line 96) is 'fs.realpathSync.native' failure → 'path.resolve' fallback + warn. However, path.resolve does not follow symlinks; an attacker creating a symlink registry entry could escape the repo_root check. Registry is gitignored so this is local privilege boundary, but attacker (unprivileged user sharing same repo) could stage a registry entry with symlinked repo_root that bypasses cross_repo protection. |
| security | MEDIUM | SESSION_ID_RE pattern allows problematic characters including dots; plan acknowledges dots are excluded (line 31: '.'), but regex still matches names like 'session.1' which may cause issues in path construction or log aggregation | Plan line 26: 'SESSION_ID_RE = /^[A-Za-z0-9_.-]+$/'. Plan acknowledges exclusion of '.' and '..' (line 31) but regex itself allows embedded dots like 'session.1.foo'. This pattern is referenced in Patterns to Mirror table (line 34) from session-end-trace.js:24-31. While 'session.1' is not '..' traversal, it creates ambiguity in file naming and could conflict with log filename conventions (e.g., 'session.log' vs 'session.1.json'). Pattern should be `/^[A-Za-z0-9_-]+$/` without dots. |
| security | MEDIUM | Plan claims D3 solves concurrent registration races by removing purge-unlink, but atomic write of separate pid files does not guarantee atomicity of diretory listing | Plan D3 (lines 80-87): 'purgeDead() unlink은 (a) 자기 PID 레코드(unregister)와 (b) 세션 디렉토리를 단독 소유하는 SessionEnd 회수에서만 일어난다'. However, list() must enumerate directory contents and call isPidAlive() on each, creating TOCTOU: process can die between readdir and isPidAlive check, or be reaped by SessionEnd in sibling session between checks. While plan accepts this risk, Task 1 Validate (line 287-289) test does not verify concurrent register+list safety. |
| security | MEDIUM | Symlink in registry directory path could allow sessionId to escape via path traversal despite regex validation | Plan references assertSafeSlug (line 34, from evidence-claim.js:56-64) which validates 'slug must be a single path segment'. Registry uses sessionDir(repoRoot, sid) = path.join(sessionDir, session_id + '/' + pid + '.json'). If sessionDir itself is a symlink (created by unprivileged attacker in shared .claude/state), then path.join could produce a path outside the intended session directory. Validation should call path.normalize or path.resolve and verify result stays within bounds. |
| test | HIGH | Task 8 can test case 9 (the critical D15 scenario where a reused PID with stale startedAtMs is protected from kill) | Plan line 170 specifies `reclaimSession({ repoRoot, sessionId, env, now, kill, isAlive, budgetMs })` — `probeProcess` is NOT listed as an injectable parameter. Task 8 line 349 requires testing: 'stale 레코드 + 재사용된 PID(probe 시작시각이 record와 3초 차이) → 미포함 + `identity_mismatch`'. Task 2 lines 293,296 specifies `isReclaimableBy` receives injected `probeProcess` and can test identity validation in isolation. Without injecting `probeProcess` into `reclaimSession`, Task 8 cannot control what `probeProcess` returns for test records, making case 9 untestable (would require real PID reuse, which is impractical). |
| test | HIGH | The design handles TOCTOU risk on D15 by ensuring `probeProcess` is called per-record in the kill path, equivalent to how `collectSiblingReuse` is passed as a function to force fresh collection | Plan line 322 explicitly mandates: '목록이 아니라 함수를 넘기므로 캐시 스냅샷이 구조적으로 불가능하다' (pass function not list so caching is structurally impossible). This design choice is made for `collectSiblingReuse`. However, line 320 specifies `reclaimSession` signature with only 5 injectable params (`kill`, `isAlive`, `now`, `budgetMs`, and implicitly `env`, `repoRoot`, `sessionId`), and line 322 only mentions passing `collectSiblingReuse` as a function to `isReclaimableBy`. No equivalent mandate exists for `probeProcess`. If `probeProcess` is not a injectable parameter, `reclaimSession` calls `isReclaimableBy` with a default/module-level `probeProcess` that the test cannot control or spy on per-record. |
| test | HIGH | Test case 9 and 9b of Task 8 (identity verification scenarios) are falsifiable via the test specification | Line 357 specifies Validate: `node --test plugins/mccp/scripts/lib/tests/session-processes-reclaim.test.js` with cases 9 and 9b at lines 349-350 requiring control over `probeProcess` return values.
