# v1.0.0 Verification Audit — codex-backoff

## Scope

Verify all 8 classification paths the user-facing flow can land in when `node codex-invoke.js adversarial-review` runs. Each row drives the wrapper to one classification via env / registry / mock companion / direct module call, captures the JSON envelope it emits, and grades:

1. **Classification accuracy** — does `result.classification` match the documented enum value for that injection?
2. **Advisory-mode contract** — `blocking` field flips per `MCCP_ALLOW_CODEX_UNAVAILABLE` (only verified for representative failure cases — exhaustive matrix lives in W10).
3. **User-visible message** — does the wrapper's `stderr` field give the operator "cause + 1-line recovery" semantics?

## F2 absorption — isolation contract

Per plan v0.5 R1 F2 attestation: the real `~/.codex/auth.json` is never read, copied, renamed, or written by W2. Every fixture lives inside `.claude/audit/_sandbox/<fixture>/` under this worktree and is referenced via the `opts.registryPath` parameter exposed by `invokeAdversarialReview()` (not via the CLI — the CLI never reads a non-default registry, by design). The four mock companions emulate real failure stderr/stdout patterns so the classifier branches the wrapper exercises are the same ones a production-installed Codex would hit. **No user escalate fired during this audit** (F2 absorption removes the only one that was reserved — the `~/.codex/auth.json` backup/restore confirm). Total user escalates this row: **0**, against an inventory budget of 1.

## Defects observed

### D2 — LOW — `not-authenticated` stderr lacks `/codex:setup` next-step hint

Row 4's stderr is the verbatim companion message (`setup_required: no credentials in $CODEX_HOME\n`). For an operator who hits this classification fresh — without prior context — there is no inline recovery hint pointing to `/codex:setup`. CLAUDE.md §3.3 documents the contract ("`/codex:setup` — 인증 + plugin 설치 상태 검증"), but the wrapper's runtime output does not.

- **Why this is LOW not MED/HIGH**: classify.js + caller layers (codex-runner, receipt-write) already inject `meta.codex_skip_reason` and the surrounding command outputs hint at the next step. The wrapper itself being terse is consistent with its single-purpose contract ("classify and surface raw companion output").
- **Possible v1.0.0 patch**: append `\nRecovery: run /codex:setup` to stderr when `classification === 'not-authenticated'` inside `makeFail()`. Single-line change.
- **DEFER_TO_BACKLOG candidate** — non-blocking for v1.0.0 ship; queue under "Codex/impeccable scope split followups" in `codex-findings-backlog.md`.

### D3 — LOW — `timeout` stderr lacks tuning hint

Row 3's stderr (`companion timed out after 250ms`) gives the threshold but does not say "raise `--timeout-ms` or check companion progress logs." Same severity-rationale as D2.
