## Kill-Switch Ancillary (`MCCP_CODEX_DESIGN_SCOPE_HONOR=0`)

The kill-switch short-circuits at command-body emission (plan.md L261,
prp-implement.md L133, pr.md analogous). When `HONOR=0`, the
`--impeccable-available` flag is omitted regardless of `skill_available`:

```
HONOR=unset, skill=true  → --impeccable-available
HONOR=1,    skill=true  → --impeccable-available
HONOR=0,    skill=true  → <no-flag>   ← kill-switch active
HONOR=0,    skill=false → <no-flag>
HONOR=unset, skill=false → <no-flag>
```

Wrapper then sees `opts.impeccableAvailable !== true` → skips
`DESIGN_SCOPE_PREAMBLE` prepend ([codex-invoke.js:144-146](../../plugins/mccp/scripts/lib/codex-invoke.js#L144-L146)).
Filter likewise degrades to identity. Net receipt audit effect: all 4
fields stay at schema defaults — **indistinguishable** from "skill missing"
or "codex disabled" via meta alone.

**Audit observation (LOW)**: receipt consumer cannot tell which of
{skill-missing, kill-switch-active, codex-disabled, no-codex-findings}
produced the default-value stamp. Cross-referencing requires STATE.md
or env snapshot at the time of the run. Not a defect — recorded as
candidate for v1.x receipt schema if disambiguation becomes load-bearing.
