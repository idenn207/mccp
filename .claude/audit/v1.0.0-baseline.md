measure the user-visible surface of all top-level `/mccp:*` commands + `/mccp:work`

fetch, `prp-commit` interactive interpretation, `pr` interactive confirm) are recorded
via spec analysis — invoking them in a single-session dogfood without their cooperator

## Findings — W1

### F-W1-1 — HIGH — `/mccp:work` classify's "no new files" probe ignores metadata-only untracked paths

- **Evidence**: Rows 11 + 12. Every classify call with `.claude/audit/v1.0.0-baseline.md` untracked returned `reason=new-files-present` regardless of staged diff composition. Override (Row 13) bypasses by skipping the probe entirely.
- **Impact**: Any user with untracked artifacts under `.claude/notes/*`, `.claude/audit/*`, or `.claude/issues/*` (the patterns mccp itself instructs users to create) is silently pinned to full chain. trivial path becomes practically unreachable except via `--trivial` override or pre-classify `git clean` — neither is documented in CLAUDE.md §1.3.
- **Fix candidate**: classify's diff probe should exclude `.claude/{notes,audit,issues,tmp}/**` and `.claude/state/STATE.md` from the "no new files" axis (treat as metadata, not as source-code change).
- **W1 affects W7**: adds a stale-doc finding to W7 docs-sync (CLAUDE.md §1.3 mentions 5-AND but not the audit-untracked contamination case).
- **W1 affects W11**: adds rubric data — Decision-Type C (user must learn `--trivial` exists) + Next-step 3 (no in-stderr hint).

### F-W1-2 — MED — `dep-check.js` `impeccable_cli.installed` disagrees with `impeccable-detect.js` Skill probe

- **Evidence**: Row 3. dep-check returned `installed:false`; main attestation recorded Skill probe pass (`impeccable-available: true`).
- **Impact**: `/mccp:setup` Phase 1 detect table prints `impeccable CLI: missing` even on machines where `~/.claude/skills/impeccable/` is fully wired and codex-invoke's `DESIGN_SCOPE_PREAMBLE` prepend is active. User gets confused or chases a phantom install.
- **Fix candidate**: `dep-check.js` to emit two fields — `impeccable_cli` (PATH probe) AND `impeccable_skill` (user-level skill probe) — instead of one ambiguous `impeccable_cli`. Setup table prints both.
- **W3 directly affected**: W3 scenarios already test impeccable Skill detection — this finding gives W3 its first row of evidence.

### F-W1-3 — MED — CLAUDE.md §1.3 misrepresents `/mccp:work` classify's actual conservative default

- **Evidence**: CLAUDE.md §1.3 documents "5-AND heuristic (file count ≤ 2, LOC ≤ 20, ext ⊂ md/txt/json/yaml/yml, no new files, no source-code signature)". The actual classify logic short-circuits on `empty-diff` (fileCount=0) → full BEFORE evaluating any AND axis (per evidence: Rows 11-13 initial probes with no diff returned `reason=empty-diff`). And `new-files-present` triggers on metadata-only untracked (F-W1-1).
- **Impact**: User mental model: "I describe a feature → mccp routes me to trivial if it's small". Actual: "I must have an existing diff with no metadata-untracked OR pass `--trivial` explicitly".
- **Fix candidate**: CLAUDE.md §1.3 short paragraph stating "classify reads the on-disk diff, not the feature string. `--trivial` / `--full` bypass diff probe. Audit/notes untracked currently count against trivial (see F-W1-1)."
- **W7 directly affected**: this is the first doc-drift row for W7 audit.

### F-W1-4 — LOW — `/mccp:receipt-write` CLI does not support `--help`

- **Evidence**: Row 4. `cli.js write --help` returned exit 1 with `--gate is required` rather than printing a usage block.
- **Impact**: user must read `commands/receipt-write.md` or source to learn the positional/flag contract. Polish-tier UX.
- **Fix candidate**: top-level `--help` in `scripts/receipt/cli.js` that lists `status` / `preflight` / `write` subcommands + each subcommand's `--help` arg list.

### F-W1-5 — LOW — `/mccp:work` classify reason field is contaminated even when the route is correct (Row 12)

- **Evidence**: Row 12. Full-intent invocation got `type=full` (correct) but `reason=new-files-present` instead of `source-code-signature`. Downstream debugging chases the audit-untracked file, not the .js change that mattered.
- **Impact**: telemetry quality issue, not user-visible at runtime. Becomes visible in `/mccp:trace` shards and `STATE.md` Last Decision context.
- **Fix candidate**: classify should evaluate AND axes in order and emit the first failing axis as the reason, not the first AND failure regardless of meaningfulness. Or filter `new-files-present` evidence through the same metadata-path exclusion as F-W1-1.
