# mccp v0.2 Architecture Notes

> **Status**: reference-only learning document, same role as
> [`docs/gate-design.md`](./gate-design.md). The runtime contract lives in
> hooks (`plugins/mccp/scripts/hooks/`), the quality / state / lib subsystems
> (`plugins/mccp/scripts/{quality,state,lib}/`), and `plugins/mccp/hooks/hooks.json`.
> Nothing here is read at runtime — this file exists so operators understand
> *why* v0.2 added a Stop-loop, STATE.md continuity, cost-based auto-handoff,
> and a single `/mccp:work` entry on top of the v0.1 receipt chain.

v0.1 fork from ECC turned "did adversarial review happen?" into a JSON
receipt chain. It did not touch the chokepoints the user listed in the
2026-06-03 brainstorming: every gate still required a human to confirm
"yes, move on". v0.2 takes the brainstorming §6 architecture verbatim and
expresses it in mccp's plugin vocabulary.

---

## 1. Pain → Module map

The brainstorming session enumerated 6 pains. v0.2 maps 5 of them to
discrete modules; the 6th (worktree fleet management) is deferred to v0.3.

| # | Pain (brainstorming) | Module | Sprint |
|---|---|---|---|
| ① | "Codex review만 잡지 사람 감시가 빠지면 그대로 흘러간다" | **Stop-loop** (`hooks/stop-review-loop.js` + `quality/runner.js`) | S8 |
| ② | "세션 중단 후 다음 세션에 떠넘김 — 컨텍스트 인계 수작업" | **STATE.md 연속성** (`state/state-writer.js` + `state/state-injector.js`) | S10a |
| ③ | "검토 시점이 잘못됨 — 결과물이 아니라 가정만 검토" | Stop-loop의 **diff 검토** 단계 (plan-codex는 가정 검토 그대로 유지, Stop-loop가 결과물 검토 보완) | S8 |
| ④ | "비용은 문제 아니지만 인계 시점 자체가 chokepoint" | **Auto-handoff** (`state/breakpoint-detector.js` + `state/session-spawner.js`, cost-based 50/80/100 USD) | S10b |
| ⑤ | "여러 mccp 명령 사이 발생하는 명령 선택 부하" | **`/mccp:work`** 단일 entry (orchestration shell — v0.2는 wrapper, v0.3에서 진정한 single-flow commit) | S11 |
| ⑥ | "Worktree 5개 동시 관리" | _out of scope (v0.3)_ | — |

A separate cross-cutting concern: **dual-reviewer escalation** (S12) — Stop-loop or
any v0.2 hook surfacing a CRITICAL or 3R-divergent verdict appends a
"Next: run /santa-loop ..." line to `fix-task.md`. Automatic santa-loop
invocation is explicitly _not_ in scope (ecc-command-gates §5 policy).

### Receipt chain crossroad

The v0.1 receipt chain ([`docs/gate-design.md`](./gate-design.md))
captures "the adversarial review happened" as a JSON file under
`<repo>/.claude/receipts/`. The Stop-loop sits **after** the
implement-codex receipt and asks a different question: not "was the plan
challenged?" but "does the resulting diff hold up to lint/typecheck/test
and (optionally) a Codex diff review?". The two layers are therefore
orthogonal and dedupe explicitly via the shared decision_id key (see
[`v0.2-state-schema.md`](./v0.2-state-schema.md) §"Cross-gate dedupe key").

### Working-directory contract (cwd vs git toplevel)

The Stop event hands the hook a `cwd` field, but the hook does **not** run quality at `cwd`. It computes `repoRoot = git rev-parse --show-toplevel` from `cwd`, then:

- `gitDiffEmpty(repoRoot)` decides the empty-diff fast-exit
- `qualityDetect.detect(repoRoot)` reads `package.json` / lockfiles from the toplevel
- `qualityRunner.run({ cwd: repoRoot, ... })` runs npm/pnpm/yarn/bun scripts at the toplevel
- `fix-task.md` and `loop-counter.json` are written under `<repoRoot>/.claude/state/`, never under `cwd`

**Implication for monorepos**: a sub-package's `package.json` is NOT consulted unless the sub-package is itself a git toplevel (separate `.git/`). Quality stages discovered at the toplevel `package.json` are what gate the loop. If a workspace root has no `scripts.test`, `scripts.lint`, etc., every stage is `skipped` and the loop passes — even when sub-packages have failing tests.

This is intentional: the toplevel is the canonical anchor for receipts, dedupe keys, and the `originating_receipts` chain. Per-sub-package enforcement is out of scope for v0.2; if it becomes needed in v0.3, the surface is an opt-in `MCCP_STOP_LOOP_QUALITY_CWD=cwd` env override rather than changing the default.

**Verified by**: S9 dogfood T-Stop-Enforce-Fail (see [.claude/PRPs/reports/mccp-v0.2-s9-dogfood-results.md](../.claude/PRPs/reports/mccp-v0.2-s9-dogfood-results.md) §"F1"). The plan's original sandbox approach failed because the hook walked up from `cwd` to the workspace toplevel; nested `git init` inside the sandbox restored the toplevel = sandbox identity and made the failing-test scenario reachable.

### `MCCP_STOP_LOOP` env semantics

| Value | Behavior |
|---|---|
| `off` | hook returns pass-through immediately, no diff inspection |
| `observe` (default) | runs all checks, prints verdict to stdout, never blocks |
| `enforce` | runs all checks, blocks Stop with fix-task.md on failure |

User-decision Q2 (2026-06-03): default = `observe` so v0.1 users do not
see a behavior change during S9 dogfood. S9 canary worktree opts into
`enforce` to prove the Stop-loop design is fit (§5 Task 10 metrics).

### `MCCP_STOP_LOOP_CODEX` env semantics (opt-in Codex review)

| Value | Behavior |
|---|---|
| unset / `0` (default) | quality runner only; Codex bridge skipped |
| `1` | after quality pass, the hook reads a pre-recorded Codex review text from `<repo>/.claude/state/codex-stop-loop-input.txt`, classifies it via `lib/codex-bridge.js`, and treats `verdict='critical'` or `escalate=true` as a failure (block + fix-task) |

**v0.2 S8 contract clarification (Reviewer B Round 1 #5)**: the Node Stop
hook cannot directly invoke `Skill(codex:adversarial-review)` — that call
runs in Claude's agent loop, not in a child process. For S8 the hook
expects an external producer to drop the Codex review text at the
documented path before the Stop event fires. Producers in scope:

- **agent-side**: a `/mccp:work` Phase 3 body can invoke
  `Skill(codex:adversarial-review)` and write the result to the file
  before ending the response. Sprint 11 will wire this end-to-end.
- **CLI-side (S9 follow-up)**: a future helper can invoke the local
  `codex exec` CLI on the diff, write the result to the file, and let
  the Stop hook pick it up. Path documented for S9 dogfood.
- **manual**: a developer can place a result text there for testing.

If the file is absent when `MCCP_STOP_LOOP_CODEX=1` is set, the hook
logs a one-line stderr notice and treats the optional review as skipped
(fail-open semantics preserved).

User-decision Q10 (2026-06-03, Codex AUTO-CRITICAL "external destination"
strangled to opt-in): default = no external Codex call. The opt-in toggle
exists so a canary worktree can measure "quality-pass-but-bad-diff %"
(Reviewer A A3, §5 Task 10 metric). If that metric exceeds 10% in S9
dogfood, v0.3 considers reverting to enforce-by-default.

## 4. Auto-handoff sequence and priority

**Implementation status**: v0.3.0 ship (Stop hook chain wired; cost-thresholds.js single-source; breakpoint-detector + session-spawner + auto-handoff hook implemented).

```
  Stop-loop PASS  ──► record safe event timestamp (stop_loop_pass)
                                     │
                                     ▼
                       ┌─────────────────────────────────┐
                       │ breakpoint-detector.js          │
                       │ - read ecc-metrics-bridge cost  │
                       │ - tier from getHandoffCost-     │
                       │   Thresholds()                  │
                       └──┬──────┬──────┬────────┬───────┘
                          │      │      │        │
                       < $50  $50-80  $80-100   >= $100
                          │      │      │        │
                          ▼      ▼      ▼        ▼
                         none   notice  soft    hard
                          │      │      │        │
                          ▼      ▼      ▼        ▼
                         pass  stderr  ┌─────────────────┐
                              inject  │ fix-task pending?│
                              only    └──┬────────────┬──┘
                                         │ yes        │ no
                                         ▼            ▼
                                      defer        AND last_event
                                      (same       within 60s
                                      session)    & in safe set?
                                                       │
                                                ┌──────┴────────┐
                                                │ yes           │ no
                                                ▼              ▼
                                          spawner         defer
                                          (writes
                                          STATE.md
                                          next_chunk)

                       hard ceiling ──► spawner unconditionally
                                        + unsafe_checkpoint=true
                                        + fix-task → next_chunk first task
```

### Priority policy (user Q5/Q8 + Codex F3 + Reviewer A A2 merged)

1. **fix-task always wins** under tier `soft` ($80–$100): handoff deferred
   until fix-task applied. Same-session policy preserves agent context.
2. **hard ceiling ($100) overrides** fix-task: forced handoff with
   `unsafe_checkpoint=true`. fix-task is _carried over_ to the next
   session as the first chunk, not skipped.
3. **`notice` ($50–$80)** is stderr-inject-only — no spawn, no STATE.md
   write. It serves as an early signal for the agent to wind down.

### `MCCP_AUTO_HANDOFF` env semantics

| Value | Behavior |
|---|---|
| `off` | no-op, single log line |
| `notify` (default) | desktop notification + stdout meta `"start new session"` |
| `spawn` | tmux new-window or Windows Start-Process; race-locked |

### Cost-threshold source of truth

`scripts/hooks/ecc-context-monitor.js` exports `getHandoffCostThresholds()`
returning `{ notice: 50, warning: 80, critical: 100 }` (USD). breakpoint-
detector imports that named export — never inlines the literals. Reviewer
A A2 caught a silent-rebase risk here: bumping these constants in v0.2
changes v0.1's pre-existing cost-warning behavior. README v0.2 section
flags it as a breaking change.

## 5. `/mccp:work` orchestration shell (Sprint 11)

v0.2's single entry is a **command wrapper**, not true single-flow
automation. The body composes the existing chain inline:

```
  /mccp:work "<request>"
    ├─► Phase 0  PRD co-creation (skipped if Trivial heuristic matches)
    ├─► Phase 1  /mccp:plan ...
    ├─► Phase 2  /mccp:prp-implement ...
    ├─► Phase 3  (Stop-loop fires automatically — wrapper does nothing)
    ├─► Phase 4  /mccp:pr ...
    └─► Phase 5  handoff line + dual-reviewer escalation note if any
```

Reviewer B B5 caught aspirational language in the original plan that
implied v0.2 eliminated all human-in-the-loop chokepoints. It does not —
plan-codex stays interactive, PR review stays interactive. v0.3 is the
sprint where the true single-flow commit happens (auto-PRD, auto-merge
on green).

### Trivial heuristic (user Q3)

`args` length ≤ 30 chars OR matches any of `[fix, typo, rename, comment,
format]` → skip Phase 0 PRD co-creation, inline mini plan instead.

## 6. Dual-reviewer escalation triggers (Sprint 12)

Stop-loop's `lib/codex-bridge.js` classifies Codex verdicts into
`{converged, divergent, critical, unavailable}`. The bridge appends
`escalate: true` when **any** of:

- `verdict === 'divergent'` AND `rounds >= 3`
- `verdict === 'critical'` (i.e. an Auto-CRITICAL catalog hit:
  secret exposure / data loss / authz bypass / external destination /
  crypto key — same catalog as `docs/gate-design.md` §"Auto-CRITICAL")

When the Stop-loop sees `escalate: true`, it appends a
`## Dual Reviewer Escalation Required` section to `fix-task.md` with the
line `Next: run /santa-loop "<original prompt>"`. Automatic santa-loop
invocation is **not** performed — that would violate the §5 "no implicit
human input bypass" policy.

## 7. State files (`<repo>/.claude/state/`)

```
.claude/state/
├── STATE.md                           # session-bridging context (git-tracked)
├── fix-task.md                        # current fix-task (git-tracked, overwritten per failure)
├── fix-task-applied.md                # rotated copy after SessionStart inject (git-tracked)
├── loop-counter.json                  # per-task fingerprint counters (gitignored)
├── *.lock                             # advisory locks (gitignored)
└── handoff-lock-<repoHash>.lock       # spawner race lock, 5min TTL (gitignored)
```

Per plan §4 `.gitignore` row, only `loop-counter.json` and `*.lock` are
gitignored. `STATE.md` / `fix-task.md` are **git-tracked** so cross-
session continuity survives worktree resets and pair-programming
handoffs (Reviewer B Round 2 surfacing — the Round 1 fix had been
applied to the schema doc only).

Schemas — including the strict frontmatter contracts, advisory-lock
protocol, and the cross-gate dedupe key (Reviewer A A5 gating) — live
in [`v0.2-state-schema.md`](./v0.2-state-schema.md).

Resume entry point (`/mccp:resume` + `state-resumption.dispatch()` +
`resume_dispatching`/`resume_dispatched` events + `dispatch_id` /
`dispatch_id_completed` / `dispatch_attempt_count` frontmatter fields) was
introduced in v1.1.0-orchestrator-s1 — see [`docs/v1.1.0-orchestrator/spike-upstream-primitives.md`](./v1.1.0-orchestrator/spike-upstream-primitives.md)
for the surrounding stage 1 context.
