# v1.0.0 Verification Audit — handoff

## Scope

W5 validates the **cost-tier × auto-handoff-mode dispatch matrix** documented
in [docs/v0.2-architecture.md](../../docs/v0.2-architecture.md) §4 (priority
policy) and [CLAUDE.md](../../CLAUDE.md) §4 (`MCCP_AUTO_HANDOFF` toggle).

Dimensions:

| Axis | Values | Source of truth |
|---|---|---|
| Cost tier (actionable) | `notice`, `warning`, `critical` | [cost-state.js:36-43](../../plugins/mccp/scripts/lib/cost-state.js#L36-L43) — default thresholds `MCCP_HANDOFF_THRESHOLDS_USD="50,80,100"` |
| Handoff mode | `off`, `notify`, `spawn` | [session-spawner.js:50-63](../../plugins/mccp/scripts/state/session-spawner.js#L50-L63) — `MCCP_AUTO_HANDOFF`, default=`notify` |

`green` (< $50) is included as a baseline row (#0) but is not part of the 3×3
matrix — detector short-circuits with `shouldHandoff=false` before mode dispatch
([breakpoint-detector.js:96-101](../../plugins/mccp/scripts/state/breakpoint-detector.js#L96-L101)).

The `warning` row is conditional on the safe-event AND-gate
([breakpoint-detector.js:118-150](../../plugins/mccp/scripts/state/breakpoint-detector.js#L118-L150)).
Cells marked `warning` below assume the safe-event AND-gate has passed
(`stop_loop_pass | receipt_write | pr_created` within 60s **AND** no
`fix-task.md` pending). AND-gate-fail sub-cases are tracked in rows 5b/5c.

## Layer 2c environment attestation

This audit was performed on a host with **no `claude` binary on PATH**
(SessionStart hook reported `claude --version probe failed (ENOENT)`).
Per CLAUDE.md §4 and architecture §4, this configuration:

- ✅ **Does not block** the auto-handoff dispatch — every cell still runs.
- ✅ **Forces** the `spawn` column to degrade to `notify` with
  `fallback_reason='claude-binary-not-found'` and a stderr banner. This is the
  v0.3.0 S10b documented behavior, not a regression.
- ✅ **Preserves** STATE.md continuity write and ledger schema in the degraded
  path — the next session-start (manually opened by the user) inherits the
  `handoff_spawn` signal and `next_chunk` exactly as if the spawn had
  succeeded.

The `spawn` → `notify` degrade therefore exercises strictly more code than
the native `notify` path (it runs the `claudeCheck()` probe + emits an
extra stderr line) and is considered the more rigorous verification surface
for rows 6 and 9.

## Open follow-ups (carry to W6 or v1.0.1)

- **OQ-W5-1** (LOW) — Row 7 (`critical × off`) currently writes a ledger
  entry with `mode='noop', fallback_reason='mode-off'` but NO STATE.md
  update and NO banner. This is consistent with the `off` contract
  ("zero side effects") but means a user who set `MCCP_AUTO_HANDOFF=off`
  for debugging gets **no warning** at the $100 ceiling. Consider an
  always-on `critical`-tier stderr signal that bypasses `off` for hard
  ceiling specifically. Defer to v1.0.1 unless dogfood surfaces missed
  ceilings.
- **OQ-W5-2** (LOW) — Row 6/9 banner text ("manual session start required
  if no new session appeared") assumes the user can distinguish "spawn
  attempted but failed" from "spawn not configured." Layer 2c users see
  the same banner on every Stop event. Consider folding
  `fallback_reason` into the banner for clarity. Defer.
- **OQ-W5-3** (NO_EVIDENCE) — Matrix does not cover non-default
  `MCCP_HANDOFF_THRESHOLDS_USD` permutations (e.g., `"10,20,30"` for
  test runs). [cost-thresholds.js](../../plugins/mccp/scripts/lib/cost-thresholds.js)
  parsing is unit-tested elsewhere; W5 takes the default thresholds as
  given. Add a permutation row if Pro pivot (v0.4.0 axis A) lands.
